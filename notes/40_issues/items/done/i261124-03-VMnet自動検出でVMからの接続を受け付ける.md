ホスト PC 上の VMware Workstation 仮想マシン（Windows 11）から `http://vm-host:8787` でチャットサーバーへアクセスできるようにする。

## 検討と背景

### 1. ポート番号（8787）の検討
- HTTP/TCP の仕様上、1 つのポート（8787）でホスト OS 上のプロセス・ブラウザおよび仮想マシンからの接続を同時に多重化して処理できる。
- したがって「listen port が不足している」わけではなく、ポート番号を増やす必要はない。

### 2. 待ち受けアドレス（バインドアドレス）の検討
- 現行のサーバー（`src/server/config.mjs`）は `HOSTS = ['::1', '127.0.0.1']` でループバックのみを待ち受けている（設計書 `p260829-01-設計.html` の「0.0.0.0 には bind しない」方針による）。
- 仮想マシンからアクセスすると、パケットはホストの VMnet 仮想アダプタ（VMnet1 / VMnet8 等）に届くが、そのインターフェースで listen していないため即座に接続拒否（ECONNREFUSED / RST）される。
- 解決策として、手動の設定ファイル管理を増やさず、かつ物理 LAN（Wi-Fi / 有線 LAN）を露出させないため、`node:os` の `networkInterfaces()` から名前が `/vmnet/i` に一致するアダプタを自動抽出し、待ち受けアドレスに追加する。

### 3. アダプタとプロトコルの選定
- `os.networkInterfaces()` では IPv6 リンクローカルアドレス（`fe80::...`）も返るが、Windows でゾーン ID なしで listen すると `EINVAL` で失敗する恐れがある。
- そのため、安全確実な IPv4（`family === 'IPv4' || family === 4` かつ `!internal`）のみを対象とする。
- 物理 LAN（Wi-Fi やイーサネット）は除外されるため、同一 LAN 上の他 PC からアクセスされるセキュリティリスクを排除できる。

### 4. 仮想マシンおよびホスト側の前提状況
- ゲスト Windows 11 の `hosts` ファイル（`C:\Windows\System32\drivers\etc\hosts`）には `vm-host` がホストの VMnet8（NAT）側 IP として追加済み。
- ホスト OS 側の Windows Defender ファイアウォールで 8787 番ポート（受信）は開放済み。
