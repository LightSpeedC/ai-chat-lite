<strong>`_data` に、空の DB の控え (`pre-ver-000000-*.db`)が 115 本 (920 KB、09/09〜10/07)溜まっていた。</strong>本番の DB の控えではない。`src/server/migrate.mjs` の `takeBackup` は、当てる DB (`dbPath`)がどこにあっても、控えを設定の置き場 (`DATA_DIR`)に書く。**テストが作った使い捨ての DB の控えが、本番の置き場に落ちていた**と見ている。

- 1 本目が 09/09 で、`tests/migrate.test.mjs` に控えを確かめるテストが入った日と同じ。`000000` は空の DB を意味する
- **未検証:** `bun test` は全ファイルを 1 つのプロセスで動かし、`config.mjs` を最初に読んだファイルの置き場のまま使い回す、と見ている。[i260916-01](#i260916-01)(bun でテスト同士の DB が混ざる)と同じ原因の可能性がある
- 本番の DB 自体には、テストの書き込みは混ざっていないようだ。`/api/connectors` の 49 件に、テスト用の ID は無かった (2026-10-15)

- [済] `_data` を掃除した (2026-10-15、利用者が実行)。消したのは、空の DB の控え 115 本、版 1〜5 を当てる前の控え 5 本、08/30 の復旧で退避したフォルダ 2 つ。残したのは、動いている `chat.db`・`-wal`・`-shm` と、最新の版の控え `pre-ver-000006`
- [済] 控えを、当てる DB と同じフォルダに書くよう直した (2026-10-15、`takeBackup` に `dbPath` を渡す)。`tests/migrate.test.mjs` に「置き場の外にある DB に当てると、控えはその DB の隣にでき、置き場には増えない」を足し、❌Red → ✅Green を確かめた。全テスト 567 件合格。流す前と後で、本番の `_data` に何も増えていない。正しい控えは版を上げるたびに 1 本しか増えないので、自動で消す仕組みは足さない
- [未] bun が設定を使い回すという見立てを確かめる。**本番の置き場を使わずに**確かめる
