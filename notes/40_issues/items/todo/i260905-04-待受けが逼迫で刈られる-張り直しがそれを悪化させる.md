<strong>止めているのは Windows ではなく Claude Code である。</strong>背面コマンドの終了通知に `stopped because the system is running low on memory` と出る。本体に `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP` という環境変数があり、**いまは未設定**。

**関連: [i260902-02](../../issues-archive.md#i260902-02)**(60 分で止められる)。<strong>あちらは経過時間で止まる話で、こちらはメモリの逼迫で刈られる話である。</strong>止め方が 2 つある。**関連: [i260902-03](#i260902-03)**(サブエージェントが指示を守らない)。着地は同じ方向を指す。

### 実測

| 見たこと | 中身 |
|---|---|
| 件数 | 08:20〜09:55 に 46 件 (html2md 28 / reviewer 8 / ai-chat-lite 6 / PlayWright 4)。**前日は 0 件** |
| 寿命 | 24〜588 秒。29〜30 秒が最頻。**時間の上限ではない** |
| 空き | 15.75 GB 中 0.7〜1.1 GB。`Memory Compression` が 2,857 MB |
| 待受けの重さ | 16 本で 240 MB。**減らしても空きは戻らない** |
| 取りこぼし | <strong>無い。</strong>読んだ位置は保存されている |

### 張り直しが悪化させている

<strong>サブエージェントで張り直すと、1 回につき claude が 5〜6 本立つ。</strong>10:51 に待受けを 2 本張り直したとき、**9 秒間に 11 本**が立った。**サブエージェントが completed になっても、そのプロセスは残る**(40 分後も生存、合計およそ 400 MB)。

**刈られる → 張り直す → claude が増える → 空きが減る → もっと刈られる**、のループになる。html2md の張り直しは 50 回で、**exit 0 は 2 回、残り 48 回が killed** だった。

### 親から直接張ると増えない

**サブエージェントを挟まず、親の `run_in_background` で起こすと claude は 1 本も増えない**(19 本のまま、2 本を 590 秒張って実測)。

> [!IMPORTANT]
> <strong>ただし刈られるのは同じである。</strong>12 時間で張り直した 2 本は、親から直接起こしたものでも同じ理由で止まった。**親の背面コマンドも対象になる。**
> つまりこれは<strong>「刈られない方法」ではなく「刈られても悪化させない方法」</strong>である。

- [未] 親から直接張る形をルールと USAGE に書くか決める
- [未] `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP` を設定するか決める (効くかは未検証)
- [未] 刈る閾値と判定の間隔を調べる
- [未] 終わったサブエージェントのプロセスが残る理由を調べる

> [!NOTE]
> <strong>2026-09-13、このマシンのメモリを 16 GB から 32 GB に物理増設した。</strong>以降は発生していない。<strong>あわせて [i260913-01](../../issues-archive.md#i260913-01) で CLI を Rust に書き直し、待受け中の実メモリも node 版 54.20 MB から 6.41 MB へ大きく減らした。</strong>この 2 つで発生条件 (空きメモリの逼迫)自体が遠のいたため、いまは実害が無い。
> <strong>ただしこれは暫定対策である。</strong>メモリ増設は環境要因の解消であり、Claude Code がメモリ逼迫で背面コマンドを刈る挙動や、サブエージェント経由だと張り直しのたびに `claude` プロセスが増える挙動そのものは変わっていない。恒久対策 (上の「やること」)は未決定のまま残るので、<strong>状態は「未」で維持する。</strong>別のマシンや、より多くのプロジェクトを同時に動かす状況では再発しうる。

> [!TIP]
> <strong>参考: 他プロジェクトからの事故共有 (`20260824-ai-pc-public`、2026-09-21)。</strong>PlayWright 実行が kill されても、子孫プロセス (`npm` → `cmd` → `playwright cli` → `Chromium`)が切り離されて 20 時間残り続けた事例。**この課題の「終わったサブエージェントのプロセスが残る理由を調べる」と同種の問題**(親を止めても子孫が道連れにならない)。確認は `psls`、停止は `taskkill /PID <根の pid> /T /F`(`/T` が無いと子が残る)とのこと。
