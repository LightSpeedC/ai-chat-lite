<strong>`rename` が相手にするのは参加者 (connector)だけで、ルームは対象外である。</strong>2026-09-13 に `html2md` を `ai-agent-tools` へ改名したとき、**ルーム名だけは手で SQL を書いて直した。**

### そのとき書いた SQL

```sql
UPDATE messages SET room_id='ai-agent-tools' WHERE room_id='html2md';
UPDATE cursors  SET room_id='ai-agent-tools' WHERE room_id='html2md';
```

**ルームを指す列はこの 2 つだけだった**(`archives` は `archive_kind='room'` の行が 0 件だったため対象外)。

> [!CAUTION]
> <strong>取りこぼしても例外は出ない。</strong>古い名前を指す行が残るだけで、静かに食い違う。**列を 1 つ見落としても、その場では何も起きない。**
> `cursors` の主キーは `(connector_id, room_id)` なので、<strong>移した先に同じ参加者の行があると衝突する。</strong>今回は 0 件だったが、次もそうとは限らない。

### 決めること

| 案 | 中身 |
|---|---|
| A | `rename` に `room` の種別を足す (`rename :<id>: room :<旧>: :<新>:`)。**connector と同じ形になり、下見と確認もそのまま使える** |
| B | 別の道具にする。**ルームは参加者と性質が違う**(持ち主がいない)ため、混ぜない |

### やること

- [未] **A と B を決める**
- [未] <strong>ルームを指す列の洗い出しを、道具側に持たせる。</strong>手で数えると次に足した列を落とす
- [未] <strong>主キーの衝突を先に見る。</strong>移す前に断る
- [未] **3 実装に入れる**(ローカルルール 2)。定義の出どころは `src/client/options.mjs`
- [未] 本文に出てくるルーム名は**書き換えない**という線引きを、資料に残す (今回 117 件が該当した)

> [!TIP]
> **検証の道具は既にある。**`tools/40_test/rename-dryrun.mjs` が、本番の写しを作って付け替えを試し、<strong>古い ID を指す行が 0 件になることを数える。</strong>本番には書き込まない (読み取り専用の接続から `VACUUM INTO` で写す)。
> ルーム側も同じ形にできる。**作る前に、この道具で確かめられるようにしておく。**
