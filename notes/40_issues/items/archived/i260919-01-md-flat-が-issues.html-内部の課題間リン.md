<strong>issues.html を html2md で変換すると、内部の課題間リンク (例: `href="#i260830-09"`)がことごとくアンカー切れになる。</strong>コミット準備で `issues.md` を再生成した際に発見した。

> [!IMPORTANT]
> **原因は `md-flat` クラス。**`<details class="issue md-flat">` は変換時に「見出し＋本文」へ展開されるが、元の `id="i260830-09"` 属性はこの展開で失われる。GitHub は見出しテキスト全体を正規化した長い文字列からアンカーを自動生成するため (例: `## **☑** i260830-09 いらなくなった参加者・ルーム・発言を片付ける手段がない` → 実際のアンカーは `i260830-09` という短い形にならない)、`#i260830-09` という決め打ちの内部リンクとは一致しない。

**実測で切り分け済み。**`md-flat` を外した状態 (コミット済み HEAD)では issues.html 内部のアンカー切れは 0 件。`md-flat` を全課題に付けた状態 (現状)では 100 件超のアンカー切れが発生する。`md-flat` 自体は課題管理ルールで定めた既定の書き方であり、issues.html の規模でこれを使う限り常に発生する。

### やること

- [済] <strong>ai-agent-tools (html2md の開発元)へ報告した。</strong>先方で **`i260921-01`**(ai-agent-tools 側の課題)として登録され、原因は先方でも確認済み (`convertDetails()` が `md-flat` 展開時に元の `<details id="...">` を受け取らず、見出しテキストだけで `##` を作っているため)。直し方は2案 (A: 見出し前に明示アンカーを差し込む／B: リンク側を GitHub のスラッグ規則に追随させる)あった
- [済] **ai-agent-tools に、html2md 本体側 (`convertDetails()`)への実装を依頼した**(案A、chat #989)。うちだけで後始末を持ちたくなかったため
- [済] <strong>先方が html2md 側を直した (案B: リンク側を GitHub のスラッグ規則に追随させる形で実装)。</strong>実測でアンカー切れは issues.html で100件超から1件まで減った。残る1件 (`i260903-02`、見出しに `-c`・`:id:` というコードを含む)は先方への追加報告が要る
- [済] `issues.md` を生成し直した
