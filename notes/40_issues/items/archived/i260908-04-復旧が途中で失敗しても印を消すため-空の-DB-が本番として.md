`tools/80_ops/restore.ps1` の `finally` が、**どこで落ちても無条件に `_data/MAINTENANCE` を消していた**。コメントも「途中で失敗しても必ず消す」と書いてあった。

> [!CAUTION]
> <strong>危ないのは、控えへ移したあと・入れ替えるまでの間だった。</strong>その間に落ちると、DB が無い状態で印が外れる。`migrate.mjs` の `DatabaseSync` は無ければ作り、起動路に DB の実在を見る門が無いため、**空の DB に版が当たって本番として立ち上がる**おそれがあった。唯一の現物は `prev-*` に残ったままで、参加者には「取りこぼしなし」が流れる。

指摘は `ai-chat-lite-reviewer` のレビュー #19 (`msg_seq` 648)・レビュー #20 (`msg_seq` 666)。実物で確かめた。

- [済] **成功した経路だけで消す形にした**。`finally` をやめ、入れ替えが終わった後に消す。失敗した経路では印を残し、**DB の有無と控えの置き場を出して人を待つ**
- [済] **復旧手順が最初から動かない実バグを直した**。`say`([0/5])・`restart`([2/5])の 2 か所とも、`$ErrorActionPreference = 'Stop'` のもとで `2>&1` を受けていた。node 側の `announceEnv` は繋ぐコマンドすべてで環境名を必ず標準エラーに書くため、**Windows PowerShell 5.1 では毎回 `NativeCommandError` になっていた**(レビュー #20 が実測で発見。`--connector-id` の直しだけでは exit 2 → exit 1 に変わっただけで症状は同じだった)。`backup.ps1` と同じ形 (その 1 行だけ `$ErrorActionPreference` を `Continue` に緩める)で両方とも直した
- [済] **`tests/restore-ps1.test.mjs` を新設。**`restore.ps1` に `-DataRoot`・`-AccessToken` を足し (本番の挙動は変えない、テスト用の差し替え口)、実際に Windows PowerShell 5.1 でスクリプトを最後まで走らせ、目印つきのデータが正しく入れ替わることを確かめる。**直す前に戻して実際に落ちることを確認してから (RED)、直して通ることを確認した (GREEN)**。全 455 件が通る
