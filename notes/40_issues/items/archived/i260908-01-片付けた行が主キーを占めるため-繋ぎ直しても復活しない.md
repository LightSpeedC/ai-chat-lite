`src/server/store.mjs` の `upsertConnector`(105-111 行)・`touchConnector`(112-116 行)・`upsertCursor`(131-137 行)の `DO UPDATE` に **`archived_seq = NULL` が無い**。

| テーブル | 主キー | 読み出しの条件 |
|---|---|---|
| `connectors` | `connector_id` | `archived_seq IS NULL`(127 ・ 128 行) |
| `cursors` | `(connector_id, room_id)` | `archived_seq IS NULL`(130 ・ 138 行) |

<strong>片付けた行が枠を占め続けるので、同じ ID の `INSERT` は必ず `DO UPDATE` に落ちる。</strong>読み出しは `archived_seq IS NULL` で弾くため、**書けるのに読めない行**になる。

> [!CAUTION]
> **読んだ位置が戻らない。**`server.mjs` 317 行の `getCursor(...) ?? getMaxSeq(...)` が毎回 null を受けるので、<strong>`poll` の起点が毎回「いまの最大値」</strong>になる。待受けを張っていない間の発言を黙って飛ばす。
> **`archive room <room>` は被害が広い。**`store.mjs` 347 行は `WHERE archived_seq IS NULL AND room_id = ?` でルームだけを絞るため、**そのルームを読んでいた全参加者**の位置を一度に壊す。

`who` と画面の参加者一覧にも永久に出ない。`join` ・ `leave` の知らせは積まれ続ける。設計書 ([p260829-01](../../../10_plan/p260829-01-設計.md) 982 行)の「**join し直しても記録があれば触らない (未読を飛ばさないため)**」が、片付けの後だけ成り立たなくなる。

`archived_seq` を `NULL` に戻すのは `restore()`(385 行)だけである。**`tests/archive.test.mjs` 128-130 行は片付け後に `getCursor` が null を返すことまで見て、そのあと書けるかを見ていない。**

指摘は `ai-chat-lite-reviewer` のレビュー #19 (`msg_seq` 648)。**主キーの定義 (版 1 の `001-initial.sql`・版 2 の `001-connector.sql`)まで実物で確かめた。**

- [済] **`DO UPDATE` で `archived_seq = NULL` に戻す形にした**。片付けた行を消して入れ直す案は採らない。`restore()` が `archived_seq` でまとめて戻すため、行を消すと戻せなくなる。**片付けは過去のものを隠すためで、ID が二度と使えなくなることではない**
- [済] 「片付けたあとに書いて、読めるか」のテストを 3 件足した (`tests/archive.test.mjs`。参加者 ・ 読んだ位置 ・ `archive room` の後)
