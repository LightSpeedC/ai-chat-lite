<strong>利用者からの提案。</strong>初めての接続 (カーソルが無い状態)の起点を、現行の「参加した時点 (`getMaxSeq`)」から、**「その日の 0 時」と「6 時間前」のうち古い方**に変える。

> [!IMPORTANT]
> 深夜早い時間帯 (例: 0 時台)に初めて繋いだ場合、「その日の 0 時」だけだと直近 1 時間程度しか遡らない。**6 時間前を下限として併記することで、日をまたいだ直後でも一定の幅を確保しつつ、日中は「その日の 0 時」で当日分をまとめて拾える**形になる。

### 関連する既存課題

- [i260909-01](#i260909-01)(済): 現行の「参加した時点＝`getMaxSeq`」という設計そのものを扱った課題。読んでいても初回は踏むという報告を受け、`wait` 起動時の案内 (`recent` の見本を出す)を足す形で対応済み。**今回の提案は、この設計自体を変える恒久対策の位置づけになる**
- [i260908-01](#i260908-01)(済): `getCursor(...) ?? getMaxSeq(...)`(`server.mjs`)という起点ロジックの実装箇所を扱ったバグ修正。今回変更するのは同じ箇所 (`?? getMaxSeq(...)` の代わりに「0 時と 6 時間前の古い方」を使う)

### やること

- [済] 「6 時間前」「その日の 0 時」の判定に使う時刻 (JST)と、境界 (ちょうど 0 時・ちょうど 6 時間前)の扱いを決める。[計画書](../../../10_plan/i260920-01-初回の起点を早める.md)に記載
- [済] `server.mjs` の該当箇所 (`handleJoin`・`handlePoll` の `getCursor(...) ?? getMaxSeq(...)`)を変更した。`time.mjs` に `jstTodayMidnight()`、`store.mjs` に `getSeqBefore(roomId, ts)` を追加し、`server.mjs` の `initialSeq(roomId)` がその2つから起点を計算する。**先にサーバー側だけ実装した際は、テストスイート全体が「初参加＝いまから」を前提にルームを使い回しており連鎖的に壊れたため、いったん差し戻して[計画書](../../../10_plan/i260920-01-初回の起点を早める.md)に対策 (テストごとに使い捨てルームにする)をまとめてから再実装した**。全テスト通過
- [済] [i260909-01](#i260909-01) の案内文 (「参加より前の発言は待ちません」)を、新しい起点に合わせて書き換えた (node 版・Rust 版とも)。「当日 0 時・6 時間前の古い方より前の発言は待ちません」に変更
