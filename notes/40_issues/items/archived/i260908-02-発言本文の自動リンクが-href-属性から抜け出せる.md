`src/web/js/markdown.js` の `escapeText`(13-18 行)が `&` ・ `<` ・ `>` の 3 文字だけを置換し、**`"` を素通しする**。41 行の自動リンクはその値を `href="../../$1"` に埋め、URL の文字集合が `[^\s&]+` なので、**空白と `&` を含まない形で `"` を混ぜた本文が href を閉じて、続きを新しい属性にできる**。

> [!CAUTION]
> <strong>他の参加者が書いた本文で、画面を開いた人のブラウザで任意の JS が動く。</strong>タグは作れないが、`on…` の属性を足せば足りる。
> **同一オリジンから `/api/admin/*` が本番では認証なしで叩ける**(`server.mjs` 740-768 行の `isAllowed` はテスト用サーバーのトークン検査だけ)。`archive` ・ `restore` ・ `exit` がすべて届くので、**片付けとサーバー停止まで画面越しに実行される**。

冒頭のコメント (1-10 行)は「**先に全体をエスケープしてから記法を処理する。この順にすれば、本文に生の HTML が含まれていてもタグとして解釈される経路が無い**」と書いている。**タグは塞げているが、属性の中は塞げていない。**

直す先は 2 つある。**`escapeText` に `"` を足す**のが素直で、41 行の URL の文字集合から `"` を外すのも要る (属性値として埋める前に確かめる形)。**どちらか一方では足りない**かどうかは、直すときに確かめる。

指摘は `ai-chat-lite-reviewer` のレビュー #19 (`msg_seq` 648)。**3 文字だけの置換と `href="../../$1"` の組み合わせ、`/api/admin/*` に認証が無いことを実物で確かめた。**

- [済] **両方直した**。`escapeText` に `"` → `&quot;` を足し、自動リンクの文字集合を `[^\s&"']+` にした (`'` も外した)。**片方に頼ると、エスケープの範囲を変えたときに黙って開く**
- [済] テストを 3 件足した (`tests/markdown.test.mjs`)。攻撃の形 (`https://example.com/a"onmouseover="alert(1)`)を入れて、**タグの中に属性が生えず本文として残る**ことを見ている
