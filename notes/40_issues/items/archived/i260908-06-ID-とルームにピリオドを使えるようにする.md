**使えるのは英数字・ハイフン・下線だけだった**(`src/client/options.mjs` の `ID_PATTERN` ＝ `^[A-Za-z0-9_-]+$`)。

<strong>プロジェクトのフォルダ名にピリオドを含むものがある。</strong>名乗る ID はフォルダ名を使う決めなので、そのままでは名乗れなかった。

<strong>使える形は「先頭・末尾には置けない」にした。</strong>末尾のピリオドは Windows がファイル名から落とすため (ID は待受けのログの名前に入る。`chat.mjs` 493 ・ `WaitLog.cs` 31 の `logs/client/yyyymmdd-hhmmss-<ID>.log`)、置けると名前が食い違う。先頭も同じ理由で禁じ、`ID_PATTERN` を `^[A-Za-z0-9_-](?:[A-Za-z0-9_.-]*[A-Za-z0-9_-])?$` にした。1 文字だけの ID (ピリオド以外)はそのまま許す。

> [!TIP]
> **「埋める前にエスケープが要る」という当初の懸念は、確かめたところ当たらなかった。**`WAITER_PATTERN` は特定の ID を式に埋めて探すのではなく、コマンドラインから ID を抜き出すだけの固定の式である。抜き出した ID は自分の ID と `===` で比べているだけで (`chat.mjs:912・924` ・ `Waiters.cs` も同型)、**ID を動的に正規表現へ組み立てている箇所は src 配下に無い**。前方一致の事故 ([i260901-07](#i260901-07))はコロンで囲む形にした時点で解消済みで、ピリオドの追加では再発しない

| どこ | 直したこと |
|---|---|
| `options.mjs` | `ID_PATTERN` ・ `WAITER_PATTERN` の文字集合 |
| `Definition.cs` | 読めなかったときの既定値を 2 か所とも揃えた |
| `Args.cs` | `IsValidId`(正規表現を使わない 1 文字ずつの判定)にピリオドと先頭・末尾の禁止を足した。**ここは `Definition.IdPattern` を見ておらず、直さないと C# 版だけ通らないままだった** |
| `server.mjs` ・ `chat.mjs` ・ `Args.cs` | 断るときの文言を「英数字・ハイフン・下線・ピリオド (先頭と末尾には置けません)」に揃えた |
| テスト | `client-connector-id.test.mjs`。先頭・末尾のピリオドを断る検査を足し、通る例にピリオド入りを足した |
| 資料 | USAGE ・ 設計書。**共通ルールの「ID に使えるのは英数字・ハイフン・下線だけ」は未反映**(別途「反映して」の指示が要る) |

node 版・C# 版とも、テスト用サーバーで `test-20260908.project` のような ID が実際に参加できること、`.bad` ・ `bad.` が両方とも同じ理由で断られることを実測した。

- [済] 使える形を決めた (**先頭・末尾には置けない**)
- [済] 出どころ (`options.mjs`)と写し (`Definition.cs`)を直した。**`Args.cs` の独自判定も揃えた**
- [済] **「埋める前のエスケープ」は不要と分かった**(上のコールアウトを参照)。動的にID を式へ組み立てる箇所が無いため
- [済] テストと資料 (USAGE ・ 設計書)を揃えた。全 414 件が通る
