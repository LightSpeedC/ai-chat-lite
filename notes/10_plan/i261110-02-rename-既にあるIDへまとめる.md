# ai-chat-lite: rename で既にある ID へまとめる

置き場を移したプロジェクトの、古い ID の記録を新しい ID へ寄せる

> 📅 作成: 2026-11-10 / 更新: 2026-11-10

[README へ戻る](../../README.md)

**対象: ai-chat-lite ／ 入力: `src/server/store.mjs` ・ `server.mjs` ・ `src/client/options.mjs` ・ `chat.mjs` ・ `src/cli-rs/` ／ 出力: 同じファイルと `tests/`、設計書。**

課題 i261110-02 (rename で、既にある ID へまとめられるようにする) の計画。file-manager の置き場が移り、旧 ID `20261019-file-manager` (発言 59 件) と新しい ID `file-manager` (発言 2 件) が並んでいる。`aichat rename` は新しい ID が使われていると断るため、まとめる指定を足す。

## 1. 決めたこと

| 番号 | 問い | 選んだ案 |
|---|---|---|
| 22-A | 既にある ID へまとめる手段 | rename に、まとめる指定を足す (DB を手で直さない) |
| 23-A | 指定のしかた | `--merge` を付けたときだけまとめる。付けなければ今までどおり断る |
| 24-A | 読んだ位置が両方の ID にあるとき | 進んでいるほうを残す |

## 2. 今ある動きと、変える点

今ある動き (変えない): 旧 ID の `connectors` ・ `cursors` ・ 発言 (差出人 ・ 宛先 ・ 本文の `@旧ID`)・ 片付けの記録を、1 つのトランザクションで新しい ID にする。新しい ID が使われていれば断る。待受けが走っていれば断る。`confirm` に旧 ID を求める。既定のルームに知らせを積む。

| 場所 | `--merge` を付けたとき |
|---|---|
| `connectors` | 旧 ID の行を消し、新しい ID の行を残す。`first_joined_at` は古いほう、`last_active_at` は新しいほうを取る |
| `cursors` | 同じルームに両方あれば、`msg_seq` ・ `acked_seq` の大きいほうを新しい ID の行に残し、旧の行を消す。片方だけなら付け替える |
| 発言 ・ 片付けの記録 | 今の rename と同じに付け替える |
| 待受け | 旧 ID ・ 新しい ID のどちらかが走っていれば断る |
| まとめ先が無いとき | ふつうの rename と同じに付け替える |

## 3. 手順

| 順 | すること |
|---:|---|
| 1 | 落ちる試験を先に書き、❌Red を確かめる (まとめ先がある場合の各テーブル、`--merge` なしは断る、新しい ID の待受け中は断る) |
| 2 | `store.mjs` に、まとめる処理を足す。`server.mjs` で `merge` を受ける |
| 3 | `options.mjs` に `--merge` を定義し、node 版と Rust 版に通す。突き合わせの試験を直す |
| 4 | 全件の試験を流し、設計書のコマンド表と API を最新にする |
| 5 | Rust 版を作り直し、指示を受けて既定の exe に写す。サーバは指示を受けて起動し直す |
| 6 | 指示を受けて、本番で `20261019-file-manager` を `file-manager` にまとめる。両方の待受けを止めてもらう |
