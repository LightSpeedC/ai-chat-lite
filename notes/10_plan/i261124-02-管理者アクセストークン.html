計画: shutdown と restart にアクセストークンを必須にする (i261124-02)

サーバー停止・再起動エンドポイント (/api/admin/exit) を管理者アクセストークンで保護する設計計画

課題 i261124-02 に基づき、aichat shutdown および aichat restart の実行時に管理者アクセストークンの照合を必須化する設計計画である。

背景と目的

現在、本番環境のサーバーはローカル通信の利便性のために認証を要求しておらず、/api/admin/exit は POST リクエストであれば誰でも呼び出せる状態にある。

課題 i261124-01 で CLI 側に --yes の確認フラグを必須化したが、API エンドポイント自体が開放されているため、外部スクリプトの直接呼び出しや AI エージェントの誤動作により、全プロジェクトの待受けを巻き込んでサーバーが停止・再起動されるリスクが残る。

目的:

サーバー停止および再起動の実行権限を、あらかじめ管理者トークン（シークレット）を保有している管理者および正規運用スクリプトに限定し、偶発的・不正なサーバー中断を根本遮断する。

管理者トークンの設計と受渡し方式

1. トークンの生成・保持方式

  • 環境変数 AICHAT_ADMIN_TOKEN: サーバー起動時に環境変数から取得する。
  • 自動生成とファイル保持: 環境変数が未指定の場合、初回起動時にランダムなトークン (UUID v4) を生成し、Git 管理外の _secrets/admin.token (権限制限フォルダ) に保存する。以降の起動ではこのファイルを再利用する。

2. API 照合方式

  • エンドポイント: POST /api/admin/exit
  • 照合方法: ヘッダ x-aichat-access-token またはリクエスト JSON 本文内の access_token フィールドを検査。
  • 不一致時: HTTP 403 Forbidden を返し、サーバーを停止・再起動しない。

3. CLI からの受渡し

  • オプション --access-token <値> (短縮 -a) による明示的指定。
  • 環境変数 AICHAT_ADMIN_TOKEN が存在する場合は自動参照。

既存運用への影響と移行計画

  • 一般コマンドへの影響: join, wait, say, recent, who 等の一般利用には一切影響しない（トークン不要のまま）。
  • 移行手順:
    1. サーバー側に管理者トークン生成・照合機能を実装（未設定時は警告ログを出して素通りさせる移行期間を設けることも可能）。
    2. CLI（Node / Rust）にトークン受渡しを実装。
    3. restore.ps1 を更新。
    4. テストスイートの全件通過を確認後、本番へ展開。
