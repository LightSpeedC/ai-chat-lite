ai-chat-lite: 待受けを止める unwait を足し、stop を shutdown に変える

待受けを止めたつもりで、サーバを落とす aichat stop を打つ取り違えを防ぐ

📅 作成: 2026-11-15 / 更新: 2026-11-15

対象: ai-chat-lite ／ 入力: src/client/options.mjs ・ chat.mjs ・ waiters-pick.mjs ・ src/cli-rs/ ／ 出力: 同じファイルと tests/ ・ tools/40_test/ ・ CHAT-USAGE.md ・ 設計書。

課題 i261115-01 の計画。今、待受けを止める専用のコマンドは無い。自分が張ったものはハーネスの TaskStop、ほかは aichat waiters が名指しした pid を強制終了で止めている。一方 aichat stop はサーバを落とすコマンドで、待受けの話と同じ「stop」の語を使っているため取り違えやすい。サーバを落とす側の名前を変え、待受けを止める口を aichat の中に作る。

決めたこと

番号問い選んだ案
35-Aサーバを落とす stop の名前shutdown に変える。--yes が無ければ落とさない
36-A待受けを止めるコマンドaichat unwait :<id>: -p <ポート> -r <ルーム> を足す
37-Aunwait の対象とするルーム渡した -r と完全に一致した待受けだけを止める
利用者の指示古い名前の stop何も実行せず、unwait だけを案内する (サーバを落とす案内は出さない)
利用者の指示unwait の出し方waiters のように、止めたもの・止めていないもの・残っているものを表で出す。全部止まらなければ正常終了にしない

今ある動きと、変える点

今ある動き (変えない): waiters の数え方と表示 (pickWaiters ・ printWaiters)。wait の動き。restart (終了コード 1 で落とし、10 秒後に起動し直させる)。サーバ側の /api/admin/exit (exit_code が 0 なら止まったまま)。守る試験: tests/client-usage.test.mjs ・ tests/cli-rs.test.mjs ・ tools/40_test/compare-cli.mjs。

コマンド今変えたあと
stopサーバを落とす (終了コード 0 で、止まったまま)何も実行しない。「stop は廃止しました。待受けを止めるなら unwait を使ってください」と出し、終了コード 2 で終わる
shutdown無い今の stop の動きを移す。--yes が無ければ、落とさずに「本番のサーバを落とします。続けるなら --yes を付けてください」と出し、終了コード 2 で終わる
unwait無い自分の ID で張った待受けのうち、接続先とルームが完全に一致した分だけを止める (3 章)

押さえること

待受けを見つける式 (WAITER_PATTERN) は、wait の前を空白か行頭に限っている。unwait の wait は前が n なので当たらないはずだが、試験で確かめる (当たると、止める道具が止める相手に数えられる)。

止めるときは、親だけでなく子のプロセス (bun など) まで止める。ローカルルール 4 節のとおり、親を止めても子は道連れにならない。自分自身の pid は止めない。

unwait の表示と終了コード

表は waiters と同じ形 (ID ・ 張り方 ・ いつから ・ 経過 ・ ルーム ・ pid) に、「結果」の列を足す。止めたあとで数え直し、残っているかを表に反映する。

結果意味どれが対象か
止めた止めたあと、数え直しても居ないID ・ 接続先 ・ ルームが完全に一致した分
止められなかった強制終了が失敗した。理由を添える同上
残っている強制終了は通ったが、数え直すと居る (子が残った等)同上
止めていない自分の ID だが、接続先かルームが違う。pid と理由 (別の場所 ・ ルームが違う) を出す自分の ID の、一致しなかった分

他プロジェクトの分は触らず、件数だけを出す (waiters と同じ)。末尾に 1 行で、止めた N 本 / 止められなかった N 本 / 残っている N 本 / 止めていない N 本 を出す。

場面終了コード
1 本以上止め、止められなかった・残っているが 0 本0
止められなかった、または残っている分が 1 本でもある1
一致する待受けが 1 本も無い (止めたものが無い)1 (「止める待受けは見つかりませんでした」と出す)
引数の誤り (接続先の省略・使えない文字)2 (waiters と同じ)

確認が要る点: 「一致する待受けが無い」を正常終了 (0) にしない、は、「止めていない事を正常終了としない」というご指示から私が選んだ。2 回目の unwait を成功扱いにしたい場合は、0 に変える。

手順
