# ai-chat-lite: 待受けを止める unwait を足し、stop を shutdown に変える

待受けを止めたつもりで、サーバを落とす `aichat stop` を打つ取り違えを防ぐ

> 📅 作成: 2026-11-15 / 更新: 2026-11-15

[README へ戻る](../../README.md)

**対象: ai-chat-lite ／ 入力: `src/client/options.mjs` ・ `chat.mjs` ・ `waiters-pick.mjs` ・ `src/cli-rs/` ／ 出力: 同じファイルと `tests/` ・ `tools/40_test/` ・ `CHAT-USAGE.md` ・ 設計書。**

課題 i261115-01 の計画。今、待受けを止める専用のコマンドは無い。自分が張ったものはハーネスの `TaskStop`、ほかは `aichat waiters` が名指しした pid を強制終了で止めている。一方 `aichat stop` はサーバを落とすコマンドで、待受けの話と同じ「stop」の語を使っているため取り違えやすい。**サーバを落とす側の名前を変え、待受けを止める口を `aichat` の中に作る。**

## 1. 決めたこと

| 番号 | 問い | 選んだ案 |
|---|---|---|
| 35-A | サーバを落とす `stop` の名前 | `shutdown` に変える。`--yes` が無ければ落とさない |
| 36-A | 待受けを止めるコマンド | `aichat unwait :<id>: -p <ポート> -r <ルーム>` を足す |
| 37-A | `unwait` の対象とするルーム | 渡した `-r` と**完全に一致した待受けだけ**を止める |
| 利用者の指示 | 古い名前の `stop` | 何も実行せず、`unwait` だけを案内する (サーバを落とす案内は出さない) |
| 利用者の指示 | `unwait` の出し方 | `waiters` のように、止めたもの・止めていないもの・残っているものを表で出す。**正常 (終了コード 0) は「最初からいない」と「止められた」だけ。それ以外は異常 (1)** |

## 2. 今ある動きと、変える点

今ある動き (変えない): `waiters` の数え方と表示 (`pickWaiters` ・ `printWaiters`)。`wait` の動き。`restart` (終了コード 1 で落とし、10 秒後に起動し直させる)。サーバ側の `/api/admin/exit` (`exit_code` が 0 なら止まったまま)。守る試験: `tests/client-usage.test.mjs` ・ `tests/cli-rs.test.mjs` ・ `tools/40_test/compare-cli.mjs`。

| コマンド | 今 | 変えたあと |
|---|---|---|
| `stop` | サーバを落とす (終了コード 0 で、止まったまま) | 何も実行しない。「`stop` は廃止しました。待受けを止めるなら `unwait` を使ってください」と出し、終了コード 2 で終わる |
| `shutdown` | 無い | 今の `stop` の動きを移す。`--yes` が無ければ、落とさずに「本番のサーバを落とします。続けるなら `--yes` を付けてください」と出し、終了コード 2 で終わる |
| `unwait` | 無い | 自分の ID で張った待受けのうち、接続先とルームが完全に一致した分だけを止める (3 章) |

> [!IMPORTANT]
> **押さえること**
> 待受けを見つける式 (`WAITER_PATTERN`) は、`wait` の前を空白か行頭に限っている。`unwait` の `wait` は前が `n` なので当たらないはずだが、**試験で確かめる** (当たると、止める道具が止める相手に数えられる)。
> 止めるときは、親だけでなく子のプロセス (`bun` など) まで止める。ローカルルール 4 節のとおり、親を止めても子は道連れにならない。自分自身の pid は止めない。

## 3. unwait の表示と終了コード

表は `waiters` と同じ形 (ID ・ 張り方 ・ いつから ・ 経過 ・ ルーム ・ pid) に、**「結果」の列**を足す。止めたあとで数え直し、残っているかを表に反映する。

| 結果 | 意味 | どれが対象か |
|---|---|---|
| 止めた | 止めたあと、数え直しても居ない | ID ・ 接続先 ・ ルームが完全に一致した分 |
| 止められなかった | 強制終了が失敗した。理由を添える | 同上 |
| 残っている | 強制終了は通ったが、数え直すと居る (子が残った等) | 同上 |
| 止めていない | 自分の ID だが、接続先かルームが違う。**pid と理由 (別の場所 ・ ルームが違う) を出す** | 自分の ID の、一致しなかった分 |

他プロジェクトの分は触らず、件数だけを出す (`waiters` と同じ)。末尾に 1 行で、`止めた N 本 / 止められなかった N 本 / 残っている N 本 / 止めていない N 本` を出す。

| 場面 | 終了コード |
|---|---|
| **最初からいない** (止める待受けも、止めていない待受けも無い) | 0 (「止める待受けは見つかりませんでした」と出す) |
| **止められた** (対象の全部が「止めた」で、止めていない待受けが無い) | 0 |
| 止められなかった、または残っている分が 1 本でもある | 1 |
| 止めていない分 (接続先かルームが違う自分の待受け) が 1 本でもある | 1 (止めた分があっても。止めたつもりにさせない) |
| 引数の誤り (接続先の省略・使えない文字) | 2 (`waiters` と同じ) |

> [!TIP]
> **利用者の指示 (2026-11-15)**: 「最初からいない時と停止できた時は正常。それ以外は異常」。最初の案では「最初からいない」も異常 (1) にしていたが、この指示で正常 (0) に変えた。**止めていない分があるときを異常にするのは、この指示の読み方である** (「それ以外」に当たると読んだ)。違う読み方なら知らせてほしい。

## 4. 手順

| 順 | すること |
|---:|---|
| 1 | 落ちる試験を先に書き、❌Red を確かめる。試験用の接続先で、待受けに見える仮のプロセスを起こし、一致 ・ ルーム違い ・ ポート違い ・ 他の ID の各場面で、止まる・止まらないを見る。`stop` の案内、`shutdown` の `--yes` なしも書く |
| 2 | `options.mjs` に `shutdown` ・ `unwait` を定義し、`stop` を案内だけの名前にする。`export-options.mjs` で JSON に書き出す (廃止したコマンドの案内 `removed_commands` を足すので、`schema` を 5 に上げ、Rust 版の `EXPECTED_SCHEMA` も合わせる) |
| 3 | node 版 (`chat.mjs`) に実装する。止める対象の選び方は `waiters-pick.mjs` に置き、試験と共有する |
| 4 | Rust 版 (`src/cli-rs/`) に同じ形を入れる。`compare-cli` に新しい通りを足し、2 本の出力を突き合わせる |
| 5 | `stop` を呼んでいる道具 ・ 資料を探して直す (`text find --recurse`)。`CHAT-USAGE.md` ・ 設計書のコマンド表を最新にする |
| 6 | 全件の試験 (`node --test` と `bun test`) を流す。結果を課題に書く |
| 7 | Rust 版を作り直す。**既定の `aichat.exe` への写しは、指示を受けてから行う** (他プロジェクトの待受けが掴んでいるため)。共通ルールの `stop` の記述が変わるので、見出し名と変わった点だけを周知する案を出す |

> [!IMPORTANT]
> **実装で計画と変えたこと (2026-11-15)**
> - <strong>終了コードの決まりを、利用者の指示で変えた。</strong>最初の計画は「止める待受けが無いときも 1」だったが、「最初からいない時と停止できた時は正常。それ以外は異常」の指示で、「最初からいない」を 0 にした (3 章の表)。
> - `schema` を 5 に上げた (上の 2 の行のとおり。計画の初めは「上げない」と書いていた)。
> - `shutdown` は、`--yes` を見る前に接続先を確かめる。Rust 版が接続先を先に見る作りなので、2 本の案内の順を揃えた。
> - `waiters` ・ `unwait` の「接続先が指定されていません」の見本に、打ったコマンドの名前を出す (`unwait` を打った人に `waiters` の見本を出していた)。
> - <strong>前からあった食い違いを見つけて直した。</strong>Rust 版の `waiters` ・ `unwait` は、使えない文字を含むルーム名 (`'public,dev'` など) を弾かず、node 版は終了コード 2 で止まっていた。突き合わせの通り (`compare-cases.json`) に足して差分を見つけ、Rust 版にも同じ検査を入れた。
> - `taskkill` の失敗は、文言を出さず終了コードだけを出す (文言は OS の言語で変わり、文字コードも合わない)。
