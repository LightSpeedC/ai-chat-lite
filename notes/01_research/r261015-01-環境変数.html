環境変数の使い方

どの環境変数を、どこで (クライアント・サーバ・道具)、どの場面で (本番・試験)使っているか。使っていないことが一目でわかる形で持ち続ける

📅 作成: 2026-10-15 / 更新: 2026-11-07

このプロジェクトのコード (src/ ・ tools/ ・ tests/ ・ deploy/ ・ bin/)が読む環境変数と、それを渡している所をまとめる。環境変数はプロセスの一覧に出ず、渡し損ねても既定値で静かに動く。どこで効いていて、どこで効いていないかを、ここで 1 か所に持つ。

変数を足す・消す・渡し方を変えたら、同じ作業の中でこの資料を直す。見直しの手順は 5 章。

この資料に入れないもの

  • 処理系や OS が自分で読む変数(NODE_OPTIONS、一時フォルダを決める TEMP など)。このプロジェクトのコードが名指しで読むものではない。Rust 版の単体テストが一時フォルダを使うのは、この類
  • 子プロセスへの素通し({ ...process.env, … })。親が持つものをそのまま渡すだけで、特定の変数を読んではいない。足している変数のほうは、上の表に入れてある

見直し方

いつ見直すか: 環境変数を足す ・ 消す ・ 渡し方を変える作業をしたとき、その作業の中でこの資料を直す。それとは別に、気になったときに下の検索で表と突き合わせる。

読んでいる所を探す

名指しで読んでいる所。表の「読む所」と突き合わせる。

git grep -n -E "process\.env\.[A-Z_]+|process\.env\[|\$env:[A-Za-z_]+|env::var" -- src tools tests deploy bin

渡している所を探す

サービスの定義と、子プロセスへ足している所。表の「渡している所」と突き合わせる。

git grep -n -E "<env |AICHAT_[A-Z_]+:" -- deploy tools tests

cmd ・ bat は SJIS なので、git grep と Grep から漏れることがある。日本語を含まない変数名なら当たることが多いが、確実ではない。text find でも探す (2026-10-15 は、AICHAT を含む cmd ・ bat は 0 本だった。検索式が cmd を走査していることは、既知の語で確かめた)。

text find "AICHAT" --path . --recurse --include "*.cmd,*.bat,*.reg"

表の直し方

  • 1 章の 2 つの表と、2 章の表を、同じ作業の中で揃えて直す
  • 消した変数は 3 章へ移す。表から黙って消さない
  • 読むが誰も渡さない (○)だけの変数が増えたら、4 章に書く
