- **戻るリンク構造**: 各ドキュメントの上部および下部に紺のホームバッジ (`⌂`) が配置され、上部には `margin-top: 18px` が確保されている。

### 3. GitHub レンダラでの検証 (check-markdown) と発見事項

GitHub Markdown レンダラ API (`check-markdown`) による実測の結果、31 ファイル中 30 ファイルは完全合格であったが、1 箇所で強調記法の崩れが検出された。

> [!NOTE]
> **検出された不具合: `notes/40_issues/issues.md` での `****` 崩れ**
> **発生箇所**: `notes/40_issues/issues.md` (i260918-01 関連テーブル行)
> ```markdown
> | フェーズ2 | CLI 側の対応 ... 対象は **node ・ Rust の 2 本****☑ 実装・全テスト通過... |
> ```
> **メカニズム**: `issues.html` 663 行目において、セル末尾の `<strong>node ・ Rust の 2 本</strong></td>` の直後のセルに `<td class="nowrap"><span class="badge b-done">☑</span>...</td>` が続いている。html2md がテーブル変換する際、前セルの閉じ `**` と後セルのバッジ強調 `**` が結合または連続し、CommonMark のパーサーでアスタリスク 4 連として解釈され太字化が解除されていた。
> **対策**: `issues.html` 側の該当セル内を `<strong>` のまま残すか、セル区切りとの間に空白を挟むことで解消する。

### 2. 失敗テストの詳細分析

**対象**: `tests/mask-log-input-ps1.test.mjs`（ケース: `mask-log.ps1 が成功したら、本実行まで進む`）

> [!NOTE]
> **原因: Windows PowerShell 5.1 における標準入力のエンコーディング不一致**
> Node.js の `execFileSync` から `powershell.exe` へ渡す `input: 'テスト語\n\nyes\n'` が、PowerShell の `Read-Host` 側で OEM/ANSI (Shift-JIS) として受信され、`繝・せ繝郁ｪ・` に文字化けしている。これにより入力行の改行解釈がズレて確認プロンプトへの `yes` が渡らず、下見後の確認で「中止しました」となって本実行（2回目の呼び出し）へ進まない。
> 10/25 の振り返り記録（`r261025-01`）において「mask-log 3 件が落ちていた」と指摘された経緯があり、2件は修正されたものの、標準入力パイプのエンコード問題に起因するこの1件が残存していた。

### 3. ファイルエンコーディング検査での発見

- **`tests/exe-swap.test.mjs` に不要な UTF-8 BOM が混入**: 共通ルール「文字コードと改行の定義ファイル」および `.editorconfig` では `[*.mjs]` は BOM 無し UTF-8 が規定されている。実測スキャンにより、本ファイルのみ先頭に `0xEF 0xBB 0xBF` が付与されていることが判明した。

## 5. アーキテクチャ・運用機能の検証

コア機能および運用基盤の設計・実装品質について評価した。

### 1. SQLite ストアと並行性

- **WAL モードと busy_timeout**: `src/server/store.mjs` において、接続時に `journal_mode = WAL`、`synchronous = NORMAL`、`busy_timeout = 5000` が確実に設定されている。
- **スキーマ管理**: `src/server/migrate.mjs` によりバージョン管理され、マイグレーション時のテーブル定義変更が安全に適用される。設計書（`p260829-01-設計.html`）のスキーマ表も `sqlite_master` から写す運用が徹底されている。

### 2. CLI 2本体制とスキーマ同期

- Node 版（`src/client/chat.mjs`）と Rust 版（`src/cli-rs/`）のオプション定義が `src/client/options.mjs` に一本化されている。
- `tools/20_build/export-options.mjs` により `cli-options.json` が出力され、Rust 版の `EXPECTED_SCHEMA` との不整合をビルド時およびテスト時（`tests/cli-rs.test.mjs`, `tools/40_test/compare-cli.mjs` 54通り）に機械検出する体制が機能している。

### 3. バックアップ・運用自動化

- `tools/80_ops/backup.mjs` により、`hourly`, `daily`, `weekly`, `monthly` の世代管理バックアップが完全自動化されている。
- `docs/ファイルで排他する.html` に記述された設計思想に基づき、Windows API / ファイルロックによる二重起動防止が実装されている。
